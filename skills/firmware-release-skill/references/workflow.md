# 完整发布工作流

本文件是 SKILL.md 三步工作流的展开说明，供 agent 遇到边界情况时参考。

## 端到端流程

```
用户请求发布
    │
    ▼
┌─ 1. 发现发布文件 ──────────────────────────────────────────────┐
│   · 无显式文件：扫描发布源目录，匹配 *_组*_*_校验0x*.bin/.hex    │
│     （解析命名兼容/不兼容日期段），bin 与 hex 成对，取 mtime 最新 │
│   · 有显式文件：使用之                                               │
│   · 空结果 → 退出码 2，报告目录与期望命名模式                       │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2. 识别分类 ──────────────────────────────────────────────────┐
│   · --category 显式指定 → 直接使用                                  │
│   · 自动：逐文件 classify（hmi > bcmu > bmu > 未知）                │
│   · 有未知文件 / 多类不一致 → 退出码 2，列出来由用户定夺             │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 3. 复制 ──────────────────────────────────────────────────────┐
│   · 目标 {repo}/{category}/ 自动创建                                  │
│   · 同名冲突：默认拒绝（FileExistsError 风格），--force 覆盖          │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 4. README 变更日志 ──────────────────────────────────────────┐
│   · 无 README → 创建最小结构                                           │
│   · 无变更日志栏 → 追加 `## 变更日志` + marker                         │
│   · 有 marker → 插入/合并当日条目                                        │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 5. git 提交 ─────────────────────────────────────────────────┐
│   · git add -A（或指定文件）→ git commit -m 生成信息                   │
│   · 非 git 仓库 / 无变化提交失败 → 退出码 1，日志已更新不撤回           │
└──────────────────────────────────────────────────────────────┘
```

## 边界情况处理

### 增量编译产物过期（本次会话实战踩坑）

**症状**：编译"成功"但 axf/hex 时间戳远早于最后一次代码修改；发布物 md5 与更早版本相同。

**根因**：Keil 增量编译按"源文件 mtime vs 对象文件 mtime"判断。当源文件 mtime
异常（早于对象文件）时，UV4 `-b` 认为无变化而跳过编译与链接，产物是旧的。

**处置**（发布前必须核对）：
1. 对比产物 mtime 与最后一次源码修改时间（`git log -1 --format=%ci`）
2. 产物过期 → 对工程执行全量重编译：`UV4.exe -r <project>.uvprojx`
3. 重编译后校验值应变化；校验值不变 = 内容没变，多半编译没真正执行

### 发布脚本同名冲突（WinError 183）

**症状**：Keil after-build 的 `update_size.py` 用 `os.rename`（不覆盖）生成
`BCMU_..._校验0xXXX.bin`，同名文件已存在时抛 `FileExistsError`，后续 hex 拼接失败。

**处置**：
1. 确认 Output 中同名文件是旧版（校验值不同）→ 删除旧文件后重跑编译
2. 或发布时 `--force`（发布目录侧）

### 无法识别 / 跨类混合

- 文件名无 BCMU/BMU/AppManager 标识（如 `S32K144-BC-H-xinguobiao.21.hex`）→
  询问用户目标目录，或要求 `--category`
- 一批文件识别结果跨类（bin 是 bcmu、exe 是 hmi）→ 报错拆分，不要一起发布

### 提交失败

- 仓库无 `.git` → 报告路径不是 git 仓库
- `git commit` 报 nothing to commit → 说明文件实际未变化（可能同名旧版）
- 任一步失败后：已执行的步骤（复制、日志）保留，向用户报告现状，不自动回滚
